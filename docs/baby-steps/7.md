
## Feature 7: Open-application inventory

Have each connected student agent report a limited inventory of applications currently open.

Collect only metadata needed for classroom management:

* Process or executable name
* Human-readable application name when available
* Stable executable identifier or path where appropriate
* Timestamp of the last report

Do not collect:

* Keystrokes
* Passwords
* Window text or document contents
* Browser history
* Chat contents
* Private file contents

Requirements:

* Use the existing authenticated client/server connection.
* Deduplicate repeated processes into useful application choices.
* Mark stale inventory clearly.
* Handle disconnected computers.
* Sanitize values before displaying them in HTML.
* Do not trust client-provided data for authorization.

Use the open-application inventory as autocomplete options when adding a blocked application.

The application autocomplete must use the same local fuzzy-search implementation:

* Arrow-key navigation
* Mouse navigation
* Enter to select
* Tab to fill the active suggestion and submit
* Escape to close
* Stable ranking

If no detected application matches the entered value:

* Allow the authorized user to add a custom application name or executable identifier.
* Clearly distinguish manually entered rules from currently detected applications.
