## Feature 5: Close the currently focused student window

Add an instructor action to request that a selected student computer close its current focused site, browser window, or foreground application.

Requirements:

* Use the existing command channel between server and student agent.
* Enforce authorization on the server.
* Do not rely only on hiding the button in the website.
* Label the action clearly.
* Add confirmation where appropriate because unsaved student work may be affected.
* Prefer a graceful close request to the foreground window.
* Do not kill random processes based on unreliable name matching.
* Do not terminate unrelated background applications.
* Return a result to the instructor:

  * Success
  * No foreground window
  * Unsupported
  * Timed out
  * Failed
* Record the action in the existing log system, or add a lightweight log if none exists.

If the current client can reliably close an active managed browser tab rather than an entire application window, use the least destructive reliable option.


## Feature 6: Class-level custom application blocking

Add a section where an authorized instructor or director can define applications that should be disabled for a class.

Before implementing, inspect how classes, rooms, locations, and sessions are represented. Use the existing representation rather than inventing an unnecessary database or framework.

Requirements:

* Rules must be scoped to the correct class, room, session, or location entity used by the project.
* Allow authorized users to add and remove application rules.
* Persist the rules using the project’s existing storage method.
* If the application currently stores state in JSON or local files, continue that pattern unless it is unsafe.
* Validate all changes server-side.
* Use a stable executable or process identifier where available.
* Store a readable display name separately.
* Avoid broad substring matching that could block unrelated software.
* Clearly show current blocked applications.
* Display errors instead of failing silently.
* Maintain compatibility with existing saved data.
