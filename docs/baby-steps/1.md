## Safety and transparency boundaries

This is visible classroom-management software, not covert monitoring software.

Do not implement:

* Hiding the agent from Task Manager
* Disguising it as an unrelated Windows process
* Rootkit behavior
* Undocumented persistence
* Attempts to defeat an administrator who intentionally stops the software
* Mutual process resurrection that ignores an authorized shutdown
* Privilege escalation
* Endpoint-security bypasses
* Collection of keystrokes, passwords, private document contents, or private messages
* An undocumented secret key combination as the only way to stop the software

Transparent behavior is allowed:

* A visible watchdog may restart the main agent after a crash or accidental close.
* The client may launch automatically through a documented startup mechanism.
* An instructor-enforced message may reappear if its display window is accidentally closed while the server still considers the message active.
* An authorized administrator must still be able to stop or uninstall the agent and watchdog.
* Processes and files must use clear iD Tech product names.
* Security-sensitive commands should be logged.
