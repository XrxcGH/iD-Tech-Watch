
## Feature 3: Message timeout

Add an optional timeout to instructor messages.

Requirements:

* Allow no timeout or a custom timeout.
* Make the time unit explicit.
* Validate values in both the browser interface and server.
* Reject malformed, negative, zero, or excessive timeout values.
* Prefer storing or transmitting an absolute expiration timestamp so reconnecting does not restart the timer.
* When the timeout expires:

  * Remove the message from the student screen
  * Update authoritative server state
  * Update the instructor interface
* Cancel any pending local timer when the instructor manually disables the message.
* Prevent expired messages from reappearing after reconnect.

## Feature 4: Custom “block for” duration

Improve the existing “block for” control.

Requirements:

* Add a custom duration input.
* Default to 1 minute.
* Keep any current preset options.
* Clearly label the time unit.
* Validate values on both client and server.
* Reject zero, negative, malformed, or excessive values (longer than 20hrs).
* Use an absolute expiration time where possible.
* Ensure reconnecting does not restart or extend a block.
* Keep the instructor countdown and server state consistent.
* Support manual cancellation.
